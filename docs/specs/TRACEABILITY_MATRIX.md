## 3. Regole automatiche

Il checker deve fallire quando:

- un heading requirement, contratto, AC o dataset è duplicato o non inventariato;
- un requirement o `DC-*` attivo non ha una obligation;
- una obligation non collega almeno un `AC-*`, una verification e un artifact;
- un `DS-*` viene usato al posto di un acceptance criterion;
- un AC, verification o artifact resta orfano;
- una decisione o un finding bloccante resta aperto;
- la readiness dichiarata diverge da quella derivata.
